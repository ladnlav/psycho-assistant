# Оценка извлечения из историй болезни

Это техметрика №2 кейса: точность и полнота извлечения из историй болезни разных шаблонов.

## Формат набора
- `data/<id>.txt` — вымышленная история болезни. Набор нарочно собран из **разных шаблонов**: порядок разделов, детализация, стиль и формат диагнозов отличаются.
- `gold/<id>.json` — эталонная разметка по схеме `app/schemas.py::ExtractionResult`.

Пример: `example_001` — образец формата, в метрику не входит (`run_eval` берёт только `hist_*`). Реальные данные пациентов **не использовать**.

Диагнозы и сопутствующие с кодом МКБ сравниваются по коду. Без кода — по тексту: совпадение, если слова одной формулировки входят в другую («ГБ 2 ст» = «ГБ 2 ст, контролируемая, риск ССО 4»).

## Набор
`hist_002`–`hist_013` — 12 вымышленных историй в разных форматах: направление 057/у, консультации невролога и психиатра, абзац с сокращениями, выписной эпикриз, телемедицина, женская консультация, осмотр на дому, консультативный лист полями. Тексты выверил врач команды: у терапевта и невролога основной диагноз — G90.8, а психиатрический — в «развёрнутом клиническом диагнозе», часто с «?».

**`gold/hist_*.json` — эталонная разметка.** Правила разметки:
- `diagnoses` — психиатрические и неврологические диагнозы, соматические — в `comorbidities`, даже если психиатрический назван «сопутствующим» (hist_005);
- `icd10` — только если код есть в тексте, иначе `null`, и метрика сравнивает текст диагноза;
- препараты — как в тексте: назначенные и рекомендованные — `current`, отменённые — `past`;
- возраст только по дате рождения — `null` (hist_013);
- отрицания («суицидальные мысли отрицает», «АГ отрицает») — не факты и не флаги;
- алкоголь, упомянутый явно, — `substance_use` и без F10 (hist_011).

Особые случаи:
- «ГТР?» в hist_003 входит в эталон как диагноз без кода; в hist_004 и hist_013 подозрение не размечено.
- hist_012: «Расстройство адаптации» и «Самоповреждающее поведение» — в эталоне текстом, без кода.
- hist_010: основной диагноз в тексте пустой — так задумано, эталон по нему пуст.

## Запуск
```bash
cd ml
python -m eval.run_eval            # нужен LLM-сервер, см. LLM_BASE_URL / LLM_MODEL в .env
```
Отчёт `eval/runs/<время>/report.json` содержит precision, recall и F1 по каждому полю и среднее время на документ. Последние результаты — в README проекта, раздел «Технические метрики».
