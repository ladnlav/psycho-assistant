# Клинический компас

Цифровой ассистент врача для ведения пациентов с тревожной и депрессивной симптоматикой. Кейс-чемпионат «Клинический компас» (Авинейро / ГК ХимРар, НМИЦ им. Сербского, Сеченовский Университет).

## Быстрый старт (всё в Docker)

Нужны [Git](https://git-scm.com/downloads) и [Docker Desktop](https://www.docker.com/products/docker-desktop/), запущенный перед командами.

```bash
git clone https://github.com/ladnlav/psycho-assistant.git
cd psycho-assistant
cp .env.example .env
docker compose up -d --build                         # первый раз — несколько минут
docker compose exec backend python -m app.seed       # демо-врач и демо-пациент с данными за 4 недели
```

- Приложение: http://localhost:8080
- API и Swagger: http://localhost:8000/docs
- ML-сервис: http://localhost:8001/docs

Демо-аккаунты: `doctor@example.com` и `patient@example.com`, пароль — `SEED_PASSWORD` из `.env`.

Остановить: `docker compose down` (данные сохранятся). `docker compose down -v` удаляет базу целиком.

## Как показать демо

Врача и пациента лучше открыть в **двух разных браузерах** (или в обычном окне и в режиме инкогнито): в одном окне браузера одновременно можно быть только одним пользователем.

1. **Врач** входит как `doctor@example.com` — видит список пациентов с последними баллами шкал. Карточку пациента не закрываем.
2. **Пациент** входит как `patient@example.com` — главная страница: самочувствие, отметка о приёме Авиандра, опросники, сообщение о побочном эффекте, чат с врачом. История демо-пациента заканчивается вчера, поэтому сегодня можно показать, как он отмечает самочувствие и заполняет GAD-7, которую уже пора пройти.
3. Пациент открывает **PHQ-9** и в пункте 9 отмечает «Several days» (русские тексты шкал ещё вносятся) → сразу видит экран помощи с телефонами 112 и 103.
4. У **врача** в ту же секунду всплывает уведомление «Критично», в карточке пациента — красный алерт с временем доставки и источниками, ниже — предложение «ОБЯЗАТЕЛЬНО» направить к психиатру.
5. Врач нажимает **«Принять»** → предложение помечается «принято врачом», направление оформлено, всё записано в журнал аудита.
6. Дополнительно: дневник и графики в карточке, «Пригласить пациента» (код для регистрации нового пациента), чат.

Повторный алерт по тому же правилу появляется только на новые данные — например, если пациент снова отметит пункт 9 в PHQ-9. Дневник, отметки о приёме и другие шкалы его не вызывают. Чтобы начать демо с чистого листа: `docker compose down -v`, затем снова `up -d --build` и `app.seed`.

## Разработка без Docker (кроме БД)

На Windows команда `python` может называться `py`.

```bash
docker compose up -d db                                  # PostgreSQL на localhost:5433

# бэкенд — http://localhost:8000
cd backend
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/alembic upgrade head
.venv/Scripts/uvicorn app.main:app --reload

# фронтенд — http://localhost:5173 (проксирует /api и /ws на :8000)
cd frontend && npm install && npm run dev

# ML-сервис — http://localhost:8001
cd ml
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/uvicorn app.main:app --reload --port 8001
```

## Тесты

```bash
cd backend && .venv/Scripts/python -m pytest -q          # 20 тестов: API, правила, база знаний
cd backend && .venv/Scripts/python -m pytest tests/test_kb.py   # только проверка kb/
cd ml && .venv/Scripts/python -m pytest -q               # 6 тестов
cd ml && .venv/Scripts/python -m eval.run_eval           # метрики извлечения (нужна LLM)

```

## LLM

ml-сервис обращается к любому OpenAI-совместимому серверу (`LLM_BASE_URL`, `LLM_MODEL` в `.env`). По умолчанию это Ollama на `localhost:11434`. В репозитории и в разработке — только вымышленные данные; реальные данные пациентов не должны уходить во внешние сервисы (152-ФЗ).

Какая модель куда помещается (сжатие до 4 бит, оценка с запасом ~1 ГБ на контекст):

| Модель | Память | GPU 4 ГБ | V100 16 ГБ | V100 32 ГБ |
|---|---|---|---|---|
| `qwen2.5:3b` | ~3 ГБ | ✓ (качество ниже) | ✓ | ✓ |
| `qwen2.5:7b` — по умолчанию | ~6 ГБ | ✕ | ✓ | ✓ |
| `qwen2.5:14b` | ~10 ГБ | ✕ | ✓ | ✓ |
| `qwen2.5:32b` | ~21 ГБ | ✕ | ✕ | ✓ |

### Модель на удалённой GPU (V100 в институте)

Схема: Ollama работает на сервере с V100, а до своего компьютера мы пробрасываем её SSH-туннелем. Для приложения модель тогда выглядит как `localhost:11434`, и ничего перенастраивать не нужно.

На V100 используем Ollama, а не vLLM: у этой видеокарты нет поддержки bf16, а свежие версии vLLM могут её не поддерживать.

**1. На сервере: проверить карту и поставить Ollama без root**

```bash
nvidia-smi                                   # объём памяти (16 или 32 ГБ) и версия CUDA

mkdir -p ~/ollama && cd ~/ollama
curl -L https://ollama.com/download/ollama-linux-amd64.tgz -o ollama.tgz
tar -xzf ollama.tgz                          # появятся ~/ollama/bin и ~/ollama/lib
```

Если по ссылке скачается архив `.tar.zst`, распаковать его так: `tar --zstd -xf <файл>`. Все сборки лежат на github.com/ollama/ollama/releases.

```bash
# добавить в ~/.bashrc, чтобы работало и после переподключения
export PATH="$HOME/ollama/bin:$PATH"
export OLLAMA_MODELS="$HOME/ollama/models"   # куда класть модели; нужно 5–20 ГБ диска
```

**2. На сервере: запустить и проверить**

```bash
tmux new -s llm                              # сессия переживёт отключение SSH
ollama serve                                 # слушает 127.0.0.1:11434
# Ctrl+B, затем D — отсоединиться; вернуться: tmux attach -t llm

ollama pull qwen2.5:7b                       # ~4,7 ГБ; потом можно сравнить с qwen2.5:14b
ollama run qwen2.5:7b "Ответь одним словом: готово"
ollama ps                                    # в столбце PROCESSOR должно быть 100% GPU
```

**3. На сервере: оценка точности извлечения** (туннель для этого не нужен)

```bash
git clone https://github.com/ladnlav/psycho-assistant.git
cd psycho-assistant/ml
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q                # 6 passed
LLM_BASE_URL=http://localhost:11434/v1 LLM_MODEL=qwen2.5:7b .venv/bin/python -m eval.run_eval
```

Отчёт с точностью и полнотой по полям сохранится в `ml/eval/runs/<время>/report.json`.

**4. На своём компьютере: SSH-туннель к модели**

```bash
ssh -N -L 11434:localhost:11434 <логин>@<адрес-сервера>
```

Окно с туннелем держим открытым, пока нужна модель. Команда `ssh` есть в Git Bash и в PowerShell на Windows 10/11. Проверить туннель можно из другого окна:

```bash
curl http://localhost:11434/api/tags         # в PowerShell: curl.exe ...
```

Ответ — JSON со списком моделей. После этого приложение (`docker compose up -d`) и `python -m eval.run_eval` на своём компьютере работают с моделью на V100. В `.env` должно стоять `LLM_MODEL=qwen2.5:7b` или та модель, что скачана на сервере.

Проверить извлечение через приложение: откройте http://localhost:8001/docs → `POST /extract` → **Try it out**, вставьте текст истории болезни → **Execute**. Первый ответ может занять 20–60 секунд, пока модель загружается в память.

**Если GPU на кластере выдаётся через очередь задач (SLURM)**

Сервер модели тогда работает на вычислительном узле, а не на узле входа. Команды зависят от правил кластера — уточните их у администраторов.

```bash
srun --gres=gpu:1 --time=08:00:00 --pty bash    # получить узел с GPU на 8 часов
hostname                                        # имя узла, например gpu07
OLLAMA_HOST=0.0.0.0:11434 ollama serve          # слушать сеть кластера, а не только localhost
```

Туннель на своём компьютере тогда идёт через узел входа:

```bash
ssh -N -L 11434:gpu07:11434 <логин>@<узел-входа>
```

Учтите: когда закончится время задачи (`--time`), сервер модели остановится. Для демо на предзащите и финале заранее сохраним результаты извлечения и запишем видео — на случай, если туннель или кластер подведут.

**Частые проблемы**

- `bind: address already in use` — порт 11434 занят. На своём компьютере это обычно локальная Ollama: остановите её или пробросьте туннель на другой порт (`-L 11435:localhost:11434`) и поставьте в `.env` `LLM_BASE_URL_DOCKER=http://host.docker.internal:11435/v1`.
- `ollama ps` показывает CPU вместо GPU — проверьте `nvidia-smi`: видна ли карта и не занята ли она чужой задачей.
- `/extract` отвечает «503: LLM недоступна» — не запущен туннель или `ollama serve`; проверьте `curl http://localhost:11434/api/tags`.
