# Клинический компас

Помощник врача-терапевта для ведения пациентов с тревогой и депрессией между визитами. Пациент в приложении отмечает самочувствие и приём препарата, заполняет шкалы и пишет врачу. Компас проверяет каждую запись по правилам из клинических рекомендаций Минздрава, инструкции ГРЛС и шкал и при риске сразу сообщает врачу. Решения о лечении и направлениях принимает только врач.

Проект кейс-чемпионата «Клинический компас» (Авинейро / ГК ХимРар, НМИЦ им. В. П. Сербского, Сеченовский Университет). Демо-препарат — Авиандр (маритупирдин). Все пациенты в репозитории вымышленные.

## Быстрый старт

Нужны [Git](https://git-scm.com/downloads) и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/).

```bash
git clone https://github.com/ladnlav/psycho-assistant.git
cd psycho-assistant
cp .env.example .env
docker compose up -d --build                         # первый раз — несколько минут
docker compose exec backend python -m app.seed       # демо-врач и демо-пациент с данными за 4 недели
docker compose exec backend python -m app.scenarios  # 6 пациентов демо-сценариев
```

Откройте http://localhost:8080. Врач — `doctor@example.com`, пациент — `patient@example.com`, пароль — значение `SEED_PASSWORD` из `.env`.

| Адрес | Что |
|---|---|
| http://localhost:8080 | Приложение пациента и врача |
| http://localhost:8000/docs | API бэкенда (Swagger) |
| http://localhost:8001/docs | ML-сервис |

Языковая модель для первого запуска не нужна: без неё работает всё, кроме извлечения фактов из истории болезни (раздел [«Языковая модель»](#языковая-модель)).

Остановить — `docker compose down`, данные сохранятся. Начать с чистой базы — `docker compose down -v`, затем снова три команды `docker compose` выше.

## Демо за 5 минут

Врача и пациента откройте в двух разных браузерах или в обычном окне и в режиме инкогнито.

1. **Врач** входит как `doctor@example.com` и видит список пациентов с баллами шкал и уровнем риска.
2. **Пациент** входит как `patient@example.com`: самочувствие за день, приём Авиандра, опросники, побочный эффект, чат с врачом.
3. Пациент открывает **PHQ-9** и в пункте 9 отмечает «В течение нескольких дней». Сразу открывается экран помощи с телефонами.
4. У врача в ту же секунду всплывает алерт **«Критично»**, в карточке — данные, источник и предложение **«ОБЯЗАТЕЛЬНО»** направить к психиатру.
5. Врач нажимает **«Принять»**: направление оформлено, решение записано в журнал аудита.
6. В карточке пациента сценария 1 или 4 врач нажимает **«Назначить Авиандр»** и видит пункты инструкции, сверенные с карточкой.

Повторный алерт по тому же правилу появляется только на новые данные пациента.

## Что умеет

**Пациент**
- раз в день отмечает тревогу, настроение и сон, отмечает приём препарата;
- заполняет GAD-7 и PHQ-9 раз в 2 недели, PHQ-4 раз в неделю, при ухудшении — раньше срока;
- сообщает о побочном эффекте и пишет врачу в чат;
- кнопкой «Нужна срочная помощь» сразу открывает телефоны экстренной и психологической помощи;
- регистрируется только по приглашению своего врача и с согласием на обработку персональных данных.

**Врач**
- видит пациентов, отсортированных по риску, и алерты в реальном времени с данными и источником;
- в карточке пациента — графики шкал и дневника, приверженность, побочные эффекты, чат, история алертов;
- принимает или отклоняет предложения «ОБЯЗАТЕЛЬНО» и «ЖЕЛАТЕЛЬНО» направить к психиатру, направляет и сам;
- при назначении Авиандра отмечает пункты листка-вкладыша из ГРЛС: противопоказания, «с осторожностью» и взаимодействия сверяются с диагнозами МКБ-10, возрастом, полом и текущими препаратами; при противопоказании из карточки назначить можно только с обоснованием.

Все клинические действия и решения врача пишутся в журнал аудита.

### Демо-сценарии

| № | Пациент | Что показывает |
|---|---|---|
| 1 | Мужчина, 63 года, ГТР, гипертония, диабет 2 типа | Назначение Авиандра после неэффективных СИОЗС, СИОЗСН и буспирона: пункты «с осторожностью» |
| 2 | Женщина, 41 год, ГТР | Ответ на терапию за 4 недели: GAD-7 с 16 до 9 |
| 3 | Мужчина, 37 лет, ГТР | Пропуски приёма и ухудшение: алерты и предложение «желательно» к психиатру |
| 4 | Женщина, 58 лет, ГТР, ХБП 3а | Противопоказание из карточки: назначить можно только с обоснованием |
| 5 | Женщина, 29 лет, ГТР | Нет записей 6 дней: напоминание пациенту с 3-го дня, алерт врачу с 5-го |
| 6 | Женщина, 30 лет, ГТР | Первое назначение: противопоказаний в карточке нет, компас просит проверить беременность, органические поражения мозга, ИМАО, почки и печень |

Пациенты сценариев — `scenario1@example.com` … `scenario6@example.com`, пароль тот же. Сценарии описаны в [scenarios/README.md](scenarios/README.md); `python -m app.scenarios s1 --reset` загружает сценарий заново.

## Как устроено

```
Браузер (PWA) ─► frontend :8080 ─ /api, /ws ─► backend :8000 ─► db :5433 (PostgreSQL)
                                                  │    └─ kb/*.yaml, scenarios/*.yaml
                                                  └─► ml :8001 ─► языковая модель (OpenAI-совместимый API)
backup ─ копия базы раз в 2 часа ─► ./backups
```

| Сервис | Что делает |
|---|---|
| `frontend` | React 19 + Mantine, PWA: интерфейсы пациента и врача |
| `backend` | FastAPI + SQLAlchemy: роли, шкалы, дневник, движок правил, алерты по WebSocket, решения врача, аудит |
| `ml` | FastAPI: `POST /extract` — извлечение из истории болезни, `POST /triage` — разметка текста пациента по риску |
| `db`, `backup` | PostgreSQL 16 и резервная копия раз в 2 часа (хранятся последние 24) |

**Принципы**
- **Решает врач.** Правило создаёт только предложение, клиническим действием его делает решение врача.
- **Правила — основа, ИИ — помощник.** Алерты создают детерминированные правила. Языковая модель только извлекает факты из истории болезни и лечение не предлагает.
- **У каждой подсказки — источник** из `kb/sources.yaml`: клиническая рекомендация Минздрава, листок-вкладыш из ГРЛС или статья о шкале.
- **Клиническая логика — в YAML.** Шкала, правило или препарат добавляются файлом в `kb/` без правки кода. При старте бэкенд проверяет базу знаний целиком и не запустится с ошибкой в ней ([kb/README.md](kb/README.md)).

### База знаний

3 шкалы (GAD-7, PHQ-9, PHQ-4), 10 правил, 1 препарат и 28 источников, в том числе КР Минздрава по ГТР и депрессии.

| Правило | Уровень | Условие | Что делает |
|---|---|---|---|
| `phq9_suicidal_ideation` | критично | PHQ-9, пункт 9 ≥ 1 | Алерт, экран помощи, «обязательно» к психиатру |
| `free_text_risk` | критично | Слова о смерти или самоповреждении в тексте пациента | Алерт, экран помощи, «обязательно» к психиатру |
| `patient_help_request` | критично | Просьба о срочной помощи с причиной | Алерт |
| `serious_adverse_event` | критично | Серьёзное нежелательное явление за 7 дней | Алерт |
| `phq9_severe` | высокий | PHQ-9 ≥ 20 | Алерт, «обязательно» к психиатру |
| `gad7_severe` | высокий | GAD-7 ≥ 15 | Алерт, «желательно» к психиатру |
| `gad7_worsening` | высокий | Рост GAD-7 на 4 балла и больше (порог значимости) | Алерт |
| `no_reports_5d` | высокий | 5 дней без записей | Алерт «свяжитесь с пациентом» |
| `low_adherence` | средний | Приём меньше 80 % дней за неделю | Алерт, напоминание пациенту |
| `no_reports_3d` | средний | 3 дня без записей | Напоминание пациенту |

Шкалы GAD-7, PHQ-9 и PHQ-4 — со свободной лицензией (Pfizer), русский текст — из валидированных адаптаций. Лицензированные шкалы (HADS, BDI-II, STAI, ISI, MMAS-8) не используются: база знаний не примет шкалу без разрешения правообладателя. Данные Авиандра взяты только из листка-вкладыша в ГРЛС.

## Технические метрики

Замеры 27.10.2026 на стенде в Docker: Intel Core i7-14700F (28 потоков), 15,5 ГБ памяти для Docker, Windows с WSL2.

| Метрика | Значение | Как получено |
|---|---|---|
| Доставка алерта врачу | медиана 20 мс, p95 25 мс; дошли 50 из 50 | `loadtest/alert_latency.py` ([loadtest/README.md](loadtest/README.md)) |
| Нагрузка | 10, 50 и 100 пользователей: медиана 7, 8 и 11 мс, p95 19, 22 и 65 мс; ошибок нет; 96 запросов/с при 100 пользователях | `loadtest/locustfile.py`, по 2 минуты на ступень |
| Восстановление из копии (RTO) | 0,5 с для базы 11 МБ, 7,9 с для 1,4 ГБ (медиана из 3 повторов) | `pg_restore` в отдельную базу (раздел «Резервные копии») |
| Потеря данных при сбое (RPO) | не больше 2 ч | Копия базы раз в 2 часа |
| Извлечение из историй болезни | диагнозы: полнота 0,89, точность 0,89, F1 0,89; ≈12 с на историю | `ml/eval`: 12 вымышленных историй, qwen2.5:14b на V100 ([ml/eval/README.md](ml/eval/README.md)) |
| Автотесты | 98: backend 87, ml 11 | `pytest`; все проходят |

На ноутбуке послабее (i7-9750H, 16 ГБ, бэкенд без Docker) доставка алерта — медиана 70 мс, p95 93 мс. При 100 пользователях там заканчивался пул соединений с базой; его увеличили до 40 соединений — по числу рабочих потоков, — и доля ошибок упала с 6,8 % до 0,2 %.

## Языковая модель

Нужна только для извлечения фактов из истории болезни. ML-сервис работает с любым OpenAI-совместимым сервером: адрес и модель задаются в `.env` (`LLM_BASE_URL`, `LLM_MODEL`; для контейнера `ml` — `LLM_BASE_URL_DOCKER`). Разбор текста пациента по риску работает без модели.

- **Ollama на своём компьютере** — по умолчанию: `ollama pull qwen2.5:7b` (около 6 ГБ видеопамяти; для 4 ГБ — `qwen2.5:3b`).
- **Ollama в контейнере** (нужна NVIDIA GPU): `docker compose --profile llm up -d ollama` и `LLM_BASE_URL_DOCKER=http://ollama:11434/v1` в `.env`.
- **Сервер с GPU.** Мы используем `qwen2.5:14b` на V100; скрипты запуска — в [ml/server/qwen_remote_v2/](ml/server/qwen_remote_v2/README.md).

После правки `.env` — `docker compose up -d ml`. Проверка: http://localhost:8001/docs → `POST /extract`. Оценка качества: `cd ml && python -m eval.run_eval`. Реальные данные пациентов не должны уходить во внешние сервисы (152-ФЗ).

## Разработка

Каждый сервис — в своём терминале, из корня репозитория. На Windows `python` может называться `py`.

```bash
docker compose up -d db                                   # PostgreSQL на localhost:5433

cd backend                                                # http://localhost:8000
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"   # Linux/macOS: .venv/bin/...
.venv/Scripts/alembic upgrade head
.venv/Scripts/uvicorn app.main:app --reload

cd frontend && npm install && npm run dev                 # http://localhost:5173, /api и /ws → :8000

cd ml                                                     # http://localhost:8001
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/uvicorn app.main:app --reload --port 8001
```

Тесты:

```bash
cd backend && .venv/Scripts/python -m pytest -q   # 87 тестов; SQLite в памяти, Docker и модель не нужны
cd ml && .venv/Scripts/python -m pytest -q        # 11 тестов
cd frontend && npm run build                      # проверка типов и сборка
```

Изменили модель данных — `cd backend && .venv/Scripts/alembic revision --autogenerate -m "что изменили"`, затем `alembic upgrade head`.

## Резервные копии

Сервис `backup` раз в 2 часа сохраняет копию базы в `backups/` и хранит последние 24. Интервал и число копий — `BACKUP_INTERVAL_S` и `BACKUP_KEEP` в `.env`. В эксплуатации копии нужно хранить на отдельном диске.

Восстановление в отдельную базу, рабочую не трогаем:

```bash
docker compose cp backups/<файл>.dump db:/tmp/restore.dump
docker compose exec db createdb -U compass compass_restore
docker compose exec db pg_restore -U compass -d compass_restore /tmp/restore.dump
docker compose exec db psql -U compass -d compass_restore -c "select count(*) from alerts"
```
