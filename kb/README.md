# База знаний (kb/)

Вся клиническая логика системы. Бэкенд читает эти файлы при старте и проверяет их схему, поэтому шкалу, препарат или правило можно добавить без изменения кода.

| Папка / файл | Что внутри |
|---|---|
| `scales/*.yaml` | Шкалы: пункты, варианты ответа, подсчёт, пороги тяжести, MCID, лицензия, источник валидации |
| `drugs/*.yaml` | Препараты **строго по инструкции из ГРЛС** |
| `rules/*.yaml` | Правила алертов и предложений врачу |
| `sources.yaml` | Реестр источников; всё остальное ссылается на id отсюда |
| `safety.yaml` | Экран безопасности пациента (контакты экстренной помощи) |

## Статусы
- `draft` — черновик (можно использовать в разработке).
- `validated` — врач сверил запись с источником.

## Правило (rules/*.yaml)
```yaml
id: phq9_suicidal_ideation          # = имя файла
title_ru: "..."
level: critical                      # critical | high | medium
when: "phq9.item9 >= 1"              # выражение над контекстом пациента (ниже)
actions: [notify_doctor, patient_safety_screen]   # + remind_patient
remind_ru: "..."                     # текст напоминания пациенту; обязателен при remind_patient
propose:                             # необязательно: предложения врачу (принимает только врач)
  - { kind: referral, to: psychiatrist, level: mandatory, reason_ru: "..." }   # mandatory | desirable
sources: [kroenke2001_phq9]          # id из sources.yaml
```

### Что доступно в `when`
| Имя | Значение |
|---|---|
| `<scale_id>.total`, `.severity`, `.item1…itemN` | Последний результат шкалы |
| `<scale_id>.<подшкала>` | Сумма пунктов подшкалы из `subscales` в файле шкалы, например `phq4.anxiety` и `phq4.depression` |
| `<scale_id>.delta_prev`, `.delta_baseline` | Изменение к прошлому и к первому измерению |
| `<scale_id>.n`, `.mcid` | Число измерений, MCID из файла шкалы |
| `ae.serious_7d`, `ae.any_7d` | Нежелательные явления за 7 дней |
| `text.critical` | За 7 дней пациент написал текст, который триаж отметил как риск (мысли о смерти, самоповреждение): сообщение врачу или описание НЯ. Размечает ml-сервис (`/triage`), решает правило; без ответа ml-сервиса текст не размечается |
| `help.requests_24h` | Просьб о срочной помощи с причиной за сутки (кнопка «Нужна срочная помощь»; причина — сообщение в чате с пометкой) |
| `pdc_7d` | Доля дней с приёмом за последние 7 завершённых дней (только дни действия назначения; `None` — нет активного назначения или < 3 дней наблюдения) |
| `days_since_report` | Дней с последней записи пациента: дневник, шкала, отметка приёма, нежелательное явление или сообщение врачу. Записей нет — с регистрации |

Если данных нет (например, шкалу ещё не заполняли), правило просто не срабатывает. Синтаксис — Python-выражения (`and`, `or`, `>=`, …), вычисляются безопасно через `simpleeval`.

### Когда алерт повторяется
Правила проверяются при каждой записи пациента, но алерт создаётся только на новые данные. У алерта хранится отпечаток: значения имён из `when` и id последнего результата шкалы.
- С тем же отпечатком правило молчит, даже если врач уже подтвердил алерт: дневник или отметка о приёме не повторяют алерт по старому PHQ-9.
- Новый результат шкалы или изменившееся значение (например, ещё одно серьёзное НЯ) — новый алерт.
- Пока алерт не подтверждён, новые данные дописываются в него, а второй алерт не создаётся. Алерт при этом уходит врачу заново: уведомление «Новые данные», в карточке — время обновления.
- Предложение направить к специалисту не создаётся, если пациент к нему уже направлен или предложение к нему от любого правила ждёт решения. Исключение: открыто только «желательно», а правило предлагает «обязательно», — «желательно» закрывается (`superseded`). Когда врач направляет пациента, остальные открытые предложения к тому же специалисту тоже закрываются. Алерт при этом создаётся как обычно.
- `days_since_report` растёт сам, без новых данных. Поэтому в отпечаток идёт не число дней, а дата последней записи: «5 дней без записей» на шестой день — тот же алерт, а не новый.

### Проверка по расписанию
Правила, где есть `days_since_report`, бэкенд проверяет ещё и по расписанию: сразу при старте и затем раз в `RULES_CHECK_MINUTES` минут (по умолчанию 60, `0` — выключить). Остальные правила проверяются только при записи пациента: у молчащего пациента нет отметок приёма, и «низкая приверженность» обгоняла бы «нет записей».

### Напоминания пациенту
Правило с `remind_patient` показывает пациенту в приложении текст `remind_ru`, пока правило срабатывает (`GET /api/patient/reminders`). Новая запись пациента снимает напоминание сама. Напоминания синие, чтобы их нельзя было спутать с красным экраном помощи.

## Препараты: проверка при назначении
Когда врач назначает препарат из `kb/drugs`, система показывает ему пункты инструкции из трёх разделов: `contraindications`, `caution` и `interactions`. Врач отмечает каждый пункт. Если противопоказание найдено в карточке пациента, назначить можно только с обоснованием; обоснование и все пункты пишутся в аудит. Система ничего не запрещает.

```yaml
contraindications:
  - id: pregnancy                     # уникален внутри препарата
    text_ru: "…"                      # дословно из инструкции ГРЛС
    when: "dx('Z33', 'Z34')"          # условие по карточке; нет when — врач проверяет сам
    ask: "sex == 'female'"            # если в карточке ничего нет — всё равно спросить (true или условие)
    check_ru: "…"                     # необязательно: чем подтвердить или исключить пункт (анализы, осмотр)
interactions:
  - id: maoi
    text_ru: "…"
    when: "taking('моклобемид')"
    severity: contraindicated         # contraindicated | caution — обязательно для взаимодействий
```

| Имя в `when` | Значение |
|---|---|
| `age` | Полных лет по дате рождения |
| `sex` | `"male"` или `"female"` |
| `dx('F10', …)` | Есть диагноз, код МКБ-10 которого начинается с одного из префиксов |
| `taking('…')` | Среди активных назначений есть препарат с таким id, МНН или названием |

Если для условия в карточке нет данных (например, даты рождения), пункт не пропускается: врач видит его с пометкой «не хватает данных». `ask` нужен для того, чего карточка обычно не знает (беременность, функция почек, недавно отменённые препараты): если условие не сработало, врач всё равно видит пункт как «проверьте у пациента». Пока разделы пустые, врач видит, что данные инструкции ещё не внесены.

## Шкалы: как часто заполнять
`schedule_days` в файле шкалы задаёт, раз во сколько дней пациенту предлагают её заполнить. Первый раз — сразу. Раньше срока пациент может пройти шкалу всегда (кнопка «Стало хуже — пройти сейчас»). GAD-7 и PHQ-9 спрашивают о последних 2 неделях, поэтому у них стоит `14`. PHQ-4 — `7` (решение команды 27.10): не каждый день, потому что она тоже спрашивает о 2 неделях, а каждый день пациент и так заполняет дневник.

## Шкалы: подшкалы
`subscales` задаёт группы пунктов со своим порогом, например у PHQ-4: тревога (GAD-2, пункты 1–2) и депрессия (PHQ-2, пункты 3–4), сумма ≥ 3 — положительный скрининг. Загрузчик проверяет, что пункты есть в шкале, а имя подшкалы не занято. В правилах сумма доступна как `phq4.anxiety`.

## Шкалы: лицензии
Свободные: PHQ-9, GAD-7, PHQ-4, HAM-A, CGI. **Не добавлять** без письменного разрешения правообладателя: HADS, BDI-II, STAI, ISI, MMAS-8 — загрузчик откажется принимать шкалу с `license.type: licensed` без `permission_obtained: true`.

Проверка базы знаний: `cd backend && pytest tests/test_kb.py`.
